# Maintaining the formalization

For installation, verification, and reading the proofs, start with the
[root README](../README.md). Run the maintenance commands below from this
`formalization/` directory.

## After a change

Review the affected mathematical statements and their correspondence to the
paper. If proofs or declaration names changed, regenerate the audit inventory:

```sh
python3 update_audit.py
```

If the paper version, statement excerpts, or reader guide changed, update
`paper_targets.json` and `../docs/STATEMENTS.md` together. Then refresh their
recorded fingerprints:

```sh
python3 check_correspondence.py --update
```

Validate the result:

```sh
python3 -m unittest discover -s tests -v
python3 verify.py
```

Review the source changes and the new `verification/report.json` before
committing. Regenerating an inventory or fingerprint does not prove a theorem;
`verify.py` performs the build and kernel audit. Its final checks reject any
change to the audited sources made during verification.

## Files to maintain

| Files | Purpose |
|---|---|
| `Analog/*.lean` | Definitions and proofs |
| `lean-toolchain`, `lakefile.toml`, `lake-manifest.json` | Pinned compiler and dependency configuration |
| `Analog.lean`, `Audit.lean`, `audit_targets.json` | Imports and declaration inventory generated by `update_audit.py` |
| `paper_targets.json`, `../docs/STATEMENTS.md` | Reviewed paper statements and their Lean correspondence |
| `COVERAGE.md`, `THEOREM_MAP.md`, `notes/` | Scope, declaration references, and detailed proof explanations |
| `verification/report.json`, `verification/build.log`, `verification/axioms.log` | Verification status, source hashes, and detailed build/audit output |

The catalog retains statement excerpts and versioned arXiv links; it does not
require the paper's LaTeX sources. The catalog checker validates the recorded
links and fingerprints. Mathematical correspondence still requires comparing
the paper's hypotheses and conclusions with the Lean declarations.

Small status logs and the duplicate `kernel-recheck.log` are generated locally
and ignored by Git. The tracked report contains the toolchain version,
dependency revision, declaration counts, and overall verification status.

The [runtime note](runtime/README.md) documents the recorded managed-workspace
audit. Its compatibility adapter is unnecessary on a standard Linux installation.

with the adapted sources.
